# 自动关闭计时与 App 在线状态对照（2026-09-04）

## 目的

检查音箱已进入“自动关闭剩余时间为 0、A2DP 未连接、AUX 不参与”的状态后，哪些私有
BLE 操作会让倒计时重新变为非零，以及 HK One 是否同时从离线变为在线。

30 秒仅为加速实验的临时测试值，不是 HK One 公开给用户的自动关闭预设。测试结束后已
恢复为 App 的 10 分钟（600 秒）选项。全程没有播放音频。

## 结果

下列操作均在 `remaining=0` 后发送，并要求设备返回应用层 ACK 或状态通知：

| 操作 | 写入类型 | 倒计时从 0 重启 |
|---|---|---:|
| 综合状态查询 | 只读查询 | 否 |
| pause / play / previous / next | 媒体动作 | 否 |
| 音量 0 | 同值写 | 否 |
| 灯开、亮度 1、速度 2 | 同值写 | 否 |
| 暖炉主题及颜色 | 同值写 | 否 |
| 暖炉颜色重置 | 重置动作 | 否（一次矩阵 + 一次复测） |
| 反馈音当前值 | 同值写 | 否 |
| 当前 EQ 完整快照 | 同值写 | 否 |
| 自动关闭设置为 600 秒 | 实际配置写 | **是** |

随后又对一组设置做“实际改变值”对照：

| 操作 | 倒计时从 0 重启 |
|---|---:|
| 灯效速度 `2→1` | **是，约 10 秒后延迟出现** |
| 亮度 `1→2` | 否（观察约 24 秒） |
| 灯开关 `1→0` | 否（观察约 24 秒） |
| 暖炉颜色 `72→71` | 否（观察约 24 秒） |
| 静音音量请求 `0→1` | 否（观察约 24 秒） |
| 反馈音 `开→关` | **是，约 10 秒后延迟出现** |
| EQ 第一段 `0→+0.5 dB` | **是，约 17 秒后延迟出现** |
| 主题暖炉 `0x14/72` → 旭日 `0x13/60` | 否（观察约 24 秒） |

速度改值后先读到 0，随后读到 19、12、5；反馈音先读到 0、随后为 19；EQ 先连续读到
两个 0、随后为 10。三者证明计时重启不是立即可见。所有改值均已恢复；音量请求 1 时
设备实际推送 3，恢复请求 0 后推送 0。

设置自动关闭为 600 秒后，连续读回的剩余时间为 596、588、581、572 秒，证明倒计时已
重新运行。HK One 仍显示缓存产品“离线”，Android 蓝牙连接历史没有出现新的连接。

在速度同值和暖炉颜色重置的单独复测中，命令均收到成功 ACK；颜色重置还返回了完整灯效
状态，但后续约 15/25 秒内倒计时一直为 0，App 也没有上线。

## 广播与 GATT

归零状态下，BlueZ 扫描观察到的候选广告只有 Fast Pair service data `FE2C:0000`，没有
HK One 2.5.4 产品解析路径使用的 PID/厂商数据。同一状态下 BlueZ 仍能建立私有 GATT、
订阅并查询。

这组结果区分了三件事：

- 私有 GATT 是否可达；
- 自动关闭倒计时是否运行；
- HK One 是否把产品显示为在线。

三者不能互相代替。

## 与早期观察的冲突

早先一次使用 600 秒配置的观察，把普通灯效写入与倒计时回到较大值相关联；本次从明确
`remaining=0` 出发的 30 秒矩阵没有复现。可能原因包括旧实验未锁定真正归零时点、状态
通知延迟、临界计时行为或其他并发活动。当前材料不足以宣称任意灯效写一定会或一定不会
重置计时。

本矩阵多数项目是同值/no-op 写入，实际改值覆盖速度、亮度、灯开关、颜色、主题切换、
低端静音音量、反馈音和一段 EQ；后续仍需覆盖其他边界值，并在更长的正式自动关闭周期
下复测。
