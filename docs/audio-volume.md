# 音频音量与第三方滑条映射

SoundSticks 5 的硬件音量同时桥接到经典蓝牙 AVRCP 和私有 BLE 控制面。BLE 综合状态
`cmd 0x42/tag 0x42` 会回报音量；官方 App 使用 `cmd 0x43/tag 0x42` 直接设置绝对音量。

Bluetooth SIG 的 AVRCP 传输规范将 Absolute Volume 定义为 7-bit 标尺：`0x00=0%`、
`0x7f=100%`。SoundSticks 5 的私有 BLE `0x42/tag 0x42` 并不原样暴露这个 7-bit 数值，
而是回报已经换算好的整数百分比 `0..100`。规范也允许音频设备采用更粗的实际档位。

参考：<https://files.bluetooth.com/wp-content/uploads/dlm_uploads/2024/10/AVRCP_v1.6.3.pdf>

## 无声受控实验

实验时香橙派已与音箱建立 A2DP/AVRCP，但 PulseAudio 蓝牙 sink 没有任何 sink input，
未播放或注入音频。只执行降低音量：

| 操作 | BLE `0x42/tag 0x42` |
|---|---:|
| 初始读取 | `0x12` (18) |
| 一次、间隔执行 `VolumeDown` | `0x0f` (15) |
| 再一次 | `0x0c` (12) |
| 继续间隔降低 | `0x00` (0) |
| 在 0 再降低 | `0x00` (0) |
| 从 0 单次 `VolumeUp` | `0x03` (3) |
| 逐档升至饱和 | `0x64` (100) |
| 在 100 再升 | `0x64` (100) |
| 实验后降回 | `0x00` (0) |

独立单步确认向下为 `-3`、向上为 `+3`，边界在 0 和 100 饱和。快速连续调用曾被合并或
丢弃，不能用调用次数推算最终状态；每次操作后应等待设备回报。

## 私有 BLE 绝对音量（App 实抓）

在 3399 没有连接 SoundSticks 5 的 A2DP、香橙派保持已静音的 A2DP/AVRCP 连接时，HK One
首页音量条从 0 移到 3，再移回 0。HCI/ATT 抓包得到：

```text
# set 3%
aa 43 04 00 42 01 03
aa 00 02 43 00             # ACK success
aa 42 04 00 42 01 03       # state notification

# set 0%
aa 43 04 00 42 01 00
aa 00 02 43 00
aa 42 04 00 42 01 00
```

随后停止 App，由另一台 BLE central 独立发送 `aa 41 00`，最终读回 `tag 0x42=0`。
这确认 `0x43` 是设置命令，值是直接百分比，并非只有 App 本机作为音频源时才有效。

## 实现建议

- 状态条：将 `0x42/tag 0x42` 的整数 `0..100` 直接作为百分比，不要再除以 127；
- 控制：纯 BLE 自动化可发送 `aa 43 04 00 42 01 VV`，其中 `VV=0..100`；也可在已经
  建立经典蓝牙音频连接时使用系统 AVRCP Absolute Volume/相对音量 API；
- 不要把 PulseAudio/PipeWire 的纯软件衰减误当成音箱硬件音量；本次把软件 sink 设为 0%
  时，BLE 音量仍保持 18；
- 不要假定音箱有 128 个物理档位。当前设备相对按键步长为 3；
- 第三方控制器设置后必须重新读取或监听 `0x42`，以设备回报为准。

深度休眠是另一层问题：当前测试中，BLE 控制本身不能可靠唤醒整机；已配对设备重新建立
A2DP/AVRCP 连接或 AUX 活动可以唤醒。因而“唤醒”和“醒来后的 BLE 音量控制”应设计成
两个独立能力。

升至最大值的测试在蓝牙 sink 强制静音、软件音量 0%、无 sink input 且没有播放/注入音频
的条件下完成。实验后硬件音量已降回 0 并复核，香橙派随后断开。平台绝对音量 API 对非
整 3 请求的取整方式仍需另行验证。
